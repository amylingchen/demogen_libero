# 数据格式与字段含义 —— 以真实样本逐项说明

> 以 `output/libero_object_100/salad_dressing/...demo.hdf5` 的 **demo_0**
> (T=144 帧,源 demo_28,目标物从源位置 (0.05,-0.10) 移到新位置 (0.065,0.087))
> 为贯穿示例。所有数值都是该条数据的真实值。

---

## 1. HDF5 结构总览

```
data/
└── demo_0/          (attrs: num_samples, object_names, object_instances,
                             phases, subtasks, subtask_vocab)
    ├── actions        (144, 7)   float64   ← 执行的动作
    ├── states         (144, 110) float64   ← MuJoCo 全量 sim state
    ├── robot_states   (144, 8)   float64   ← 机器人紧凑状态
    ├── rewards        (144,)     uint8     ← 末帧成功标记
    ├── dones          (144,)     uint8     ← 末帧结束标记
    ├── phase_id       (144,)     int32     ← 细粒度阶段索引(配 attr `phases`:
    │                                         move/grasp/move/place + 每段目标物体)
    ├── subtask_id     (144,)     int32     ← 粗粒度闭词表标签(配 attr `subtasks`:
    │                                         transit/move/idle,论文口径)
    └── obs/
        ├── agentview_rgb / eye_in_hand_rgb        (144,256,256,3) uint8
        ├── agentview_depth / eye_in_hand_depth    (144,256,256)   uint8  厘米
        ├── agentview_depth_mm / eye_in_hand_depth_mm (144,256,256) uint16 毫米
        ├── agentview_seg / eye_in_hand_seg        (144,256,256)   uint8  实例分割
        ├── ee_pos (144,3) · ee_ori (144,3) · ee_states (144,6)
        ├── gripper_states (144,2) · joint_states (144,7)
        ├── obj_pos  (144,7,3)  ← 7 物体世界坐标真值
        └── obj_quat (144,7,4)  ← 7 物体姿态四元数(xyzw)
```

**时序对齐(重要)**:`obs/*[t]` 是执行 `actions[t]` **之前**的观测
(步前对齐)。所以 `states[0]`/`ee_pos[0]`/第 0 帧图像 = 初始场景,
训练 `obs[t] → actions[t]` 的 BC 映射不会学到"到位后重放动作"。

## 2. 逐字段说明(带 demo_0 实际值)

### actions (T,7) — OSC 位姿增量指令

```
t=0   : [ 0.067  0.215 -0.117 -0.019  0.061 -0.    -1. ]
t=60  : [ 0.206  0.     0.686  0.     0.079 -0.     1. ]
t=143 : [ 0.     0.     0.     0.     0.     0.    -1. ]
```

| 维 | 含义 | 量纲 |
|---|---|---|
| [0:3] | EE 平移增量 dx,dy,dz | 归一化 ±1 ↔ ±5cm/步 |
| [3:6] | EE 旋转增量(轴角) | 归一化 |
| [6] | 夹爪指令 | -1 张开 / +1 闭合 |

解读:t=0 向 (+x,+y) 前进、微降(去抓 y=0.087 的新目标位),夹爪张开;
t=60 抓住后大幅 +z(0.686 ≈ 3.4cm/步)上提,夹爪保持 +1;
t=143 是收尾保持帧(全零 + 张开)。

### obs/ee_pos (T,3)、obs/ee_ori (T,3)、obs/ee_states (T,6)

EE 世界坐标位置(米)与姿态(**轴角**,rad);ee_states = [pos, ori] 拼接。

```
t=0   : ee_pos=[-0.140 -0.007  0.255]   ee_ori=[3.135 -0.002 -0.106]
t=60  : ee_pos=[ 0.043  0.087  0.124]   ← 已到目标物上方,正下探
t=143 : ee_pos=[-0.022  0.263  0.206]   ← 篮子上空
```

`ee_ori ≈ [π, 0, ~0]` 即夹爪竖直朝下(绕 x 转 180°),第三分量是腕部 yaw。

### obs/gripper_states (T,2) — 两指开度 qpos

```
t=0: [0.035 -0.035](全开)   t=60: [0.017 -0.019](夹着瓶身)   t=143: [0.039 -0.039](释放后全开)
```

两指对称,|值|≈0.04 为全开;夹住物体时开度=物体半径,可反推是否真握住。

### obs/joint_states (T,7) — 机械臂 7 关节角(rad)

### robot_states (T,8) — 紧凑机器人状态

`[ee_pos(3), ee_ori 轴角(3), gripper_qpos(2)]`,
即 t=0 时 `[-0.140 -0.007 0.255 | 3.135 -0.002 -0.106 | 0.035 -0.035]`
= ee_states 与 gripper_states 的拼接,给下游一个免拼接的向量。

### obs/obj_pos (T,7,3)、obs/obj_quat (T,7,4) — 物体真值位姿

7 个物体的顺序由 attr `object_names` 给出(与 seg id 对齐):

| idx | 物体 | seg id | demo_0 t=0 位置 | t=143 位置 |
|---|---|---|---|---|
| 0 | salad dressing 1(目标) | 60 | [0.065 0.087 **0.073**](地面) | [-0.016 0.277 **0.090**](**篮内**) |
| 1 | basket 1 | 70 | [-0.012 0.274 -0.005](固定) | 同左 |
| 2..6 | ketchup/soup/cream/milk/tomato | 80..120 | 摆放位或场外 (x≥2) | — |

四元数是 **xyzw** 约定、世界系。目标物 z 随时间 0.073→(抓起)→0.090
可直接做 3D 位置监督;`obj_pos[t,0]` 落在篮子 xy 即任务完成的几何证据。

**形状固定为 7,不随场上物体数变化**:未上场的干扰物也有条目,值为
场外停放坐标(x = 2.0/2.4/2.8/3.2/3.6, y = 2.0)。这样下游可按固定索引
batch(顺序 = object_names = seg id 顺序)。在场掩码自行生成:

```python
in_scene = obj_pos[:, :, 0] < 1.0   # (T,7) bool
```

训练时对场外物体务必 mask(它们的坐标是合法数值,直接回归会教坏网络);
也可用 scene_log 的 `distractor_joints` 得到上场清单。

### states (T,110) — MuJoCo 全量状态

`[time(1), qpos(nq), qvel(nv)]` 展平。用途:精确复现任意帧
(`env.set_init_state(states[t])`)、离线重渲染。物体自由关节在 qpos 中的
槽位见 `object_geometry`/管线代码,但**下游不需要解它**——obj_pos 已直给。

### rewards / dones (T,)

稀疏成功标记:全程 0,**末帧** `rewards[-1]=1, dones[-1]=1`(成功轨迹)。

### phase_id (T,) + attr `phases` — 细粒度阶段(动作词 + 每段目标物体)

`phase_id[t] ∈ {0,1,2,3}` 索引 demo attr `phases` 表,每段带动作词与目标:

```json
[{"phase":0,"action":"move", "target":"salad dressing 1","start":0,  "end":44,
  "instruction":"move the gripper to the salad dressing"},
 {"phase":1,"action":"grasp","target":"salad dressing 1","start":44, "end":64,
  "instruction":"grasp the salad dressing"},
 {"phase":2,"action":"move", "target":"basket 1",        "start":64, "end":110,
  "instruction":"carry the salad dressing to the basket"},
 {"phase":3,"action":"place","target":"basket 1",        "start":110,"end":144,
  "instruction":"place the salad dressing into the basket"}]
```

约定:阶段 0/1 的 target = 待抓物体,阶段 2/3 的 target = 篮子;
grasp 含抓前位置修正与二次抓取,place 含末尾保持帧。metainfo 同步含
"phases"。与下方粗粒度 subtask(论文口径,抓-搬-放合为一个 move)互补:
细粒度用 phases,论文对齐用 subtasks。

### subtask_id (T,) + attr `subtasks` — 闭词表子任务(主分段)

`subtask_id[t]` 是 attr `subtask_vocab`(18 词:15 原语 + transit/idle/other)
的索引:demo_0 中 `15=transit, 0=move, 16=idle`。区间表在 attr `subtasks`:

```json
[{"action":"transit","object":"salad dressing 1","destination":null,
  "instruction":"move the gripper to the salad dressing","start":0,"end":50},
 {"action":"move","object":"salad dressing 1","destination":"basket 1",
  "instruction":"move the salad dressing into the basket","start":50,"end":124},
 {"action":"transit","object":null,"destination":null,
  "instruction":"retreat the gripper","start":124,"end":141},
 {"action":"idle","object":null,"destination":null,
  "instruction":"keep the arm stationary","start":141,"end":144}]
```

字段含义:`action` 词表动作;`object` 该子任务交互/朝向的物体
(每个子阶段的目标物体);`destination` 放置目的地(仅 move 有);
`instruction` 简短语言指令;`[start,end)` 帧区间。边界约定:
move 从**首次闭爪**(接触)到**末次开爪**(释放)——抓-搬-放是一个
move,二次抓取也折叠在内。

**两套标注的边界为何不同**(同一条 demo_0:phases 的 grasp 起于 44,
subtasks 的 move 起于 50):phases 把**抓取前的位置修正帧(settle,
44~50,夹爪尚未闭合)**计入 grasp 段;subtasks 按论文口径以**夹爪-物体
接触(首次闭爪指令)**为界,settle 帧仍属 transit。两者各自内部一致,
混用边界时注意。

### 图像与分割

- `*_rgb`:256×256,**已翻转为正立方向**(与原始 LIBERO 的 OpenGL 倒置不同);
- `*_depth`:真实深度按 **1cm=1 级** 量化的 uint8(255 封顶≈2.55m);
- `*_depth_mm`:同一深度按 **1mm=1 级** 的 uint16(实际无损),
  点云/薄物体几何用它;
- `*_seg`:实例分割,`0=背景, 50=机器人末端(仅夹爪), 60=目标物,
  70=篮子, 80/90/100/110/120=干扰物`(顺序=object_names)。

### demo 级 attrs

| attr | 含义 |
|---|---|
| `num_samples` | 帧数 T |
| `object_names` / `object_instances` | 7 物体显示名 / 实例名(定义 obj_pos 与 seg id 顺序) |
| `phases` | 细粒度阶段表(action 词 + 每段 target + 指令 + 帧区间,配 phase_id) |
| `subtasks` / `subtask_vocab` | 粗粒度子任务区间表(配 subtask_id)/ 18 词表 |

## 3. metainfo.json(每条 demo 一项)

```
keys: phases, subtasks, success, initial_state, task_nouns, task_description,
      target_object, goal_object, object_names, exo_boxes, ego_boxes
```

- `phases` / `subtasks`:与 HDF5 attrs 相同的两套分段表(细/粗粒度),
  方便只读 metainfo 的下游直接拿到分段与每段目标物体;

- `target_object: "salad dressing 1"`、`goal_object: "basket 1"` —— 显式目标,
  下游不必解析任务名;
- `exo_boxes / ego_boxes`:逐帧 2D 检测框(agentview / 腕部相机),
  格式 `{物体名: [seg_id, [x, y, w, h]]}`,坐标**除以图宽高归一化**。
  例 demo_0 第 0 帧目标物:`[60, [0.5625, 0.4766, 0.0781, 0.1680]]`
  = 框左上角在 (0.56W, 0.48H),宽 0.078W、高 0.168H;
- `initial_state`:110 维初始 sim state(评估复现场景用);
- `task_nouns / task_description`:`["robot","salad dressing 1","basket 1"]` / 任务句。

## 4. scene_log.json(溯源,每条 demo 一项)

```
demo_0: scene_id=0, source_demo=demo_28, seed=1009,
        target_old_xy=[0.050,-0.100] → target_new_xy=[0.065, 0.087],
        basket_delta=[-0.013, 0.020],
        distractor_joints=[milk, ketchup, tomato_sauce], n_distractors=3
```

含义:这条轨迹由源 **demo_28** 合成,目标物从源位置平移到新位置
(即合成用的 `obj_t` = new−old),篮子抖动 `basket_delta`(= `tar_t`),
场上放了哪 3 个干扰物。同一 `scene_id` 的两条 demo 摆放完全相同、源不同。
